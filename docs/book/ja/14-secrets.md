# 秘密と玄関


## そもそも誰が呼んでよいのか

これらすべての前に、リクエストはプリンシパルにならなければならない。そして長いあいだ、それはあまりに容易になれた。ベアラトークンがないとき、サーバは二つのヘッダ — `X-Telemachus-User` と `X-Telemachus-Team` — に落ち、それをそのユーザーへ解決していた。ノートパソコンの上ではこれは便利である。スクリプトがトークンを鋳造せずに誰かとして振る舞える。しかしネットワークのアドレスに結び付けられたインスタンスでは、これはログインであり、しかも無料のログインだった。そのネットワーク上のどの呼び出し元も、自分が名乗ったとおりの誰かであり、そのユーザーが持つすべての権限を持った。これがどこに位置するかに注意してほしい — ロールの検査、スコープ、組織のゲート、セッション方針の*前*である。そのどれも、プリンシパルが存在するまで走らない。その層での身元の誤りは、その上のどの制御でも捕まえられない。

いまヘッダが尊重されるのは信頼された相手からだけである。ループバック、あるいはリバースプロキシが本当にそこで終端しているために運用者が `TMACH_TRUSTED_HEADER_PEERS` で名指したアドレスである。私的に見えることを理由に信頼されるものは何もない — 「10.x は内部だ」は、他人のネットワークについての仮定である。`POST /api/bootstrap` も同じように門を構えている。初期化されていないインスタンスは最初に呼んだ者のものになり、LAN の上ではそれは他人だからである。ループバックに到達できない運用者は、代わりに秘密を提示する。

この規則は直接試験できるよう、それ自身の小さなモジュールに住んでいる。これは聞こえるより重要である。どのスモークもサーバと同じホストで走るので、スモークが他人*である*ことは決してできず、この穴は一年分のスモークを生き延びた。

## 何がハッシュ化され、何ができないのか

パスワードと API トークンはハッシュとして保存される。トークンは環境に置いた胡椒を鍵とする HMAC-SHA-256 であり、プロセスの環境を伴わないデータベースのダンプでは再現できない。胡椒を回せば全員が一度にサインアウトする。これは立派な緊急手段であり、回せるようにしてある理由でもある。トークンはいまや期限も持つ。セッションは三十日、コンソールが発行した API トークンは九十日。期限のない行は依然として「無期限」なので、更新によって誰かがサインアウトすることはない。

三つの秘密はハッシュ化できない。比較されるのではなく*使われる*からである。TOTP の種はコードを生成する。S3 の秘密鍵は署名を検証する HMAC の鍵になる。push 型の実行基盤の鍵は、自分のリクエストに署名する。この三つはかつて平文で置かれていた。だから一つのダンプ — バックアップ、レプリカ、チケットに貼られた `pg_dump`、盗まれたボリュームのスナップショット — があれば、そのすべてを再現できた。

## 残りを封じる

それらは AES-256-GCM で封じられ、鍵は環境から来る。データベースから来ることは決してない。この主張は意図して狭く、そして正確に述べる価値がある。コードにあった以前の注記が半分だけ正しかったからである。これは**ダンプ**を守り、**ホスト**に対しては何もしない。サーバとして動いている攻撃者は、自分自身の環境から鍵を読める。しかしダンプはその環境を伴わずに旅をする。そして本来あるべきでない場所へたどり着くのは、ダンプのほうである。

    enc:v1:<key-id>:<nonce>:<ciphertext+tag>

この接頭辞を持たないものは平文であり、そのまま読まれる。だから鍵の採用はマイグレーションではなく、停止時間も要らない。行は書き換えられるときに封じられ、残りは CLI が封じる。同じ CLI が回転も行う — 以前の鍵が読み、現在の鍵が書く — そしてこれは意図してサーバが起動時にすることではない。起動時に打ち間違えた鍵は、誰も持っていない鍵ですべての行を封じてしまう。鍵をまったく使わずに動かすことも引き続き支持される。それが「データベースが信頼境界である」という立場であり、変わったのは、それが静かに受け継がれるのではなく、起動時の一行と管理の状態表示に見えるようになったことだけである。

二つの細部が重みを持つ。各値は、自身の列と行の ID を追加の認証データとして封じられる。だから一つの行から持ち出して別の行へ貼った暗号文は開かない — 書き込み権限を持つ者が、既知の秘密を別のプリンシパルの上へ移すことはできない。そして開かない封印された値は*例外を上げる*。空文字列へ劣化してはならない。空の TOTP の種は、誰かの二要素認証を静かに無効にしてしまう。

## 二要素認証と、戻る道

パスワードは変更でき、アクセスキーは再発行できる。TOTP の種は、それを使うことによって回転させることができない。だから漏れた種は永久のものになっていた — そこで、取り消せるようにした。ユーザーは自分のものを切ることができ、運用者は誰のものでも失効させられる。どちらも監査される。これで漏洩は覆える。失くした電話は覆えないので、登録のときに一度しか使えない**回復コード**を十個渡す。コードは TOTP のコードが通る場所ならどこでも通る。種と違い、コードは比較*される*ので、トークンと同じようにハッシュ化される。

価値があるのは小さな決定のほうである。照合は大文字小文字とハイフンを許す。そして文字の集合からは人が混同する文字を落としてある。これらは声に出して読まれ、紙から打ち込まれるものだからである。コードを使うのは、それを照合するのと同じ一文である。だから同時の二つのサインインが同じコードを使うことはできない。使われた行は削除されずに残る。だから「すでに使われた」が「発行されていない」と区別できたままになる。再発行は集合ごと置き換える。紙の上の一揃いは、そのアカウントを開くものについての全部の真実であるべきだからである。そして二要素認証の取り消しは、コードも一緒に削除する。

## セッションはどれだけ続くか

二つの時計がある。別々の攻撃に答えるからである。**無操作**のタイムアウトは、放置された机を限る。**絶対**の上限は、使われている盗まれたトークンを限る。そちらは決して無操作にならない。同梱の既定値は三十分と八時間 — OWASP 自身の帯のうち、もっとも支障の少ない端である — そしてどちらかに `null` を置けば、その軸に上限はない。これを明示的に綴ってあるので、「設定しなかった」と「切った」が同じに見えることはありえない。

統べられるのは**セッション**だけである。マシン用のトークンは設計上ずっと無操作であり、それを無操作で切るのは静かな障害である。だから API とワーカーのトークンは除外される — そしてトークンがどちらであるかを言うパラメータは、除外される側を既定値にしている。だからそれを忘れた呼び出し元は、トークンが昔からそうであったように振る舞うトークンを鋳造する。時計は、隣にある文字列のタイムスタンプではなくエポックの列である。文字列の `CURRENT_TIMESTAMP` は方言ごとに書式が違い、それを比較する規則は一方では見えず、他方では間違っているからである。

インスタンスが方針を定め、会社はそれを**厳しく**できるが、緩めることは決してできない。実効値は軸ごとに二つのうち厳しいほうである。これは意図してブランディングの逆である。ブランディングでは会社の文書が丸ごと勝つ — ブランディングは見た目であり、こちらは制御であって、床を所有するのはインスタンスである。強制は `resolve-token` にあり、他のどこにもない。ベアラがプリンシパルになる唯一の場所である。期限の切れたセッションは理由を添えて失効させられる。だからトークンの一覧がなぜ終わったのかを言えるし、期限の切れたセッションを使って蘇らせることもできない。

コンソールは、ポインタの動きではなく最後の**リクエスト**を基準に残り時間を数える。サーバが測るのはリクエストなので、マウスで駆動される時計は、サーバがすでに期限切れにしたセッションを元気に生きているものとして表示してしまう。

## コンソールの方針

すべての応答は基本となるヘッダの組を運び、コンソールはすべてを同一オリジンに限る Content-Security-Policy を運ぶ。そのスクリプトの出所はいまや `'unsafe-inline'` ではなく**リクエストごとのナンス**である — 前者は、注入されたスクリプトタグを実行させてしまう指定である。

これを手に入れるには、方針の一行より多くの費用がかかった。ナンスはインラインのイベントハンドラを認可できず、コンソールはそれを百四十一個使って作られていた。いまはすべて委譲されたリスナーである。描画のときにクロージャのレジストリへの添字を保持するデータ属性を書き、イベント種別ごとに一つのリスナーがそこへ配る。呼び出しの式は読める場所に残り、その引数はいま、文字列へエスケープして入れて解析し直すのではなく本物の値である — これによって、アポストロフィを含む見出しが自分のボタンを壊しうるという一群の引用符バグも消えた。スタイル属性は許されたままである。二百五十個が残っており、注入された CSS は注入されたスクリプトよりはるかに小さな獲物である。

一つのハンドラがテンプレートリテラルではなく単引用符の文字列の中に座っていたので、そのレジストリ呼び出しは決して補間されず、導線の送信ボタンは死んだ文字列として出荷された。どの静的検査もそれを見なかった。ブラウザのテストがボタンを押し、時間切れになった。いまはインラインのハンドラと、まさにその取り残しの両方に静的検査がある。方針が保たれるのは、それらが保たれているあいだだけだからである。
