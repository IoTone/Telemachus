# 運用の覚書


- **経路は定義の場所で固定する。** ウェブサーバはリクエストを処理しているあいだ、現在のディレクトリを自分のウェブルートへ向け直す — パッケージとして導入した場合は、読み取り専用の Nix ストアの中である。遅延して解決される相対経路は、そのストアを狙う。ブロブのルートは構造上絶対経路であり、ユニットテストがそれを検査し、サーバは相対経路では起動を拒否する。これは一度出荷されてしまった。起動は健全で、すべてのユニットテストが通り、最初のドキュメント保存が「Permission denied」で失敗した。

- **クォータは待ち行列を止める。** ワークフローのステップはスケジューラのジョブであり、チームが AI 予算の内側にあるときだけ受け入れられる。既定の一日二千トークンでは、一括の下書きや一括の抽出は最初の数ジョブで止まり、停止したように見える。先に `ai.tokens.total` を上げること。自動化のカードが残りの予算を表示しているのは、この理由である。

- **一メガバイトを超えるアップロードにはリスナーの上限を上げる必要がある。** そうでなければ、下にいるウェブサーバが応答を一切返さずに接続を落とす。

- **コンソールは起動時に自分の HTML をキャッシュする。** 編集を反映するには再起動すること。

- **マルチテナンシーはフラグを立てるために一度の再起動を要する。** その後に会社を迎え入れるのに再起動は要らない。

- **PDF のテキスト抽出には poppler-utils が必要である。** 抽出器が欠けていればインデックス化の実行は意図して失敗する。どの PDF も何か月も静かに検索不能であることがないようにである。

- **バックアップを取る前に、保存時の秘密について決めること。** 鍵を設定していなければ、データベースのダンプはすべての TOTP の種と S3 の秘密鍵を平文で運ぶ — それは支持される選択であり、いまは見える選択である。鍵の採用はコマンド一つで停止時間もない。鍵をデータベースと同じバックアップに入れておいても何も得られない。鍵を失えば、すべての二要素認証を再登録し、すべてのアクセスキーを再発行することになる。

- **サーバを更新すればワーカーも更新することになる。** pull 型のワーカーは、すべての心拍と結果に確保の隔離トークンを返さなければならない。返さないものは 409 を受ける。リファレンスのワーカーはそれを送るが、第三者のワーカーは歩調を合わせて更新する必要がある。

- **テーマは拒否されうる。** コンソールの配色は書き込みの時点で検証され、コントラストのゲートを通る。だから読めない組み合わせを求めた運用者は、サインインの画面で気づくのではなく、どの対がどれだけ足りないのかを告げられる。

`docs/ops/` の下のランブックが、ドキュメント保管庫、ワークフローエンジン、マルチテナンシーを運用者の言葉で扱っている。
