# コードの地図


## 層

サーバはモジュール一つ、`server/main.rkt` であり、意図的に薄い。リクエストを解析し、プリンシパルを解決し、`domain/` を呼び、応答を符号化する。製品として間違いうるものはすべて `domain/` の中にあり、そこは HTTP を何も知らず、ユニットスイートが直接動かす対象である。

| モジュール | 担当 |
|:---|:---|
| `domain/authz` | プリンシパル、ロール、権限カタログ、`can?`、付与、トークン、監査 |
| `domain/db` | マイグレーション。起動時に適用され、方言に依存しない |
| `domain/repo` | ドキュメント保管庫：オブジェクト、バージョン、ブロブ、共有、来歴、トリガ、パイプラインのツール |
| `domain/flow` | ワークフローエンジン：仕様の検証、束縛、実行のリデューサ |
| `domain/sched` | ジョブスケジューラと同時実行の調停 |
| `domain/quota` | 使用量の台帳と上限 |
| `domain/agent` | ツールレジストリ、エージェントループ、プラグインローダ |
| `domain/ai` | モデル実行：一回の呼び出し、ストリーム、あるいは模擬の代替 |
| `domain/i18n` | カタログ、ICU 書式、lint、翻訳管理 |
| `domain/kg` | 知識グラフ |
| `domain/apps` | 検索、翻訳 — 残りを組み合わせて作られたアプリケーション |
| `domain/orgs` | マルチテナンシー：チームの上にある組織 |
| `domain/beta` | オンボーディングの導線 |

## 四つの小さなライブラリ

`pkgs/` には、TMach について何も知らず、そのまま外へ持ち出せるコードが入っている。

`db-kit/portable` は Racket の `db` をそのまま置き換えるもので、PostgreSQL では `?` のプレースホルダを `$n` に書き換える。`db` ではなく必ずこちらを require すること。忘れても SQLite では何も起こらず、PostgreSQL で `syntax error at or near "AND"` として失敗する — そしてテストファイルも生の SQL を発行するので、この規則はテストにも当てはまる。

`web-kit` は JSON の制御プレーン向けに Racket の `web-server` を包み、さらに `web-kit/http1` を加える。これはリクエストの本体をポートとして扱う HTTP/1.1 のリスナーである。二つ目が存在するのは、S3 エンドポイントが数ギガバイトのファイルを運ぶからであり、そして `Expect: 100-continue` に本体の最初の読み取り時点で遅延して応答しなければならないからである。そうすることで、読む前に拒否するハンドラはバイト列を一切受け取らずに済む。

`cli-kit` はコマンドラインツールの引数解析と、終了コードの契約である。ツールには「うまくいった」と「壊れた」は言えたが、ドメインが入力を*拒否した*とは言えなかった。これは別の答えであり、別の対応を要する — 入力を直すのか、運用者を呼び出すのか。いまは四つの結果がある。`0` は実行され、結果が標準出力にある。`2` は拒否で、常に理由を伴うエラーオブジェクトが返る。`1` は実行できず、標準出力は*空*である。`64` は CLI の誤用で、標準エラーに出る。このうち二つは文書化ではなく強制されている。理由のない拒否は却下される（それは `2` の終了コードを着た `1` である）。そして実行されなかった処理は標準出力に何も書かない。誰かに成果物を手渡してはならないからである。

`sha2-kit` は libcrypto の上の SHA-256 と HMAC-SHA-256 である。プラットフォームの知識を持たないので `domain/` の中のモジュールではなくパッケージであり、FFI を使うので `crypto.rkt` — その契約は「ネイティブ依存なし」である — とは分けてある。正しさは NIST のベクタに固定されている。バインディングにおける危険は署名が間違っていることであり、ベクタはそれをただちに教えてくれる。

## プリンシパル一つ、検査一つ

すべてのリクエストは*プリンシパル*に解決される。ユーザー ID、チーム ID、運用者フラグ、任意の組織ロール、そして API トークンと S3 キーについては、発行者ができたことに上限をかけるスコープの一覧である。プラットフォームにおけるすべての認可判断は一つの関数 `can?` であり、次章で説明する。ハンドラは `require-perm` を呼ぶ。拒否は例外を上げ、サーバがそれを翻訳済みの 403 に変える。

## 開いてみるファイル

`server/main.rkt`（require 群と `HANDLERS` の表を流し読みする）、`domain/authz/authz.rkt`、`pkgs/db-kit/portable.rkt`。
