# ルート表と生成されるリファレンス


## 制定ではなく宣言

すべての HTTP ルートは `server/routes.rkt` の一つのエントリである。メソッド、経路のパターン、ハンドラの鍵、どう認証するか、何の権限を強制するか、どの機能フラグの後ろにいるか、そして一行の説明である。サーバは一つの表で鍵をハンドラに結び付け、どちらかの側が相手に無いものを名指していれば起動を拒否する。説明のないエンドポイントは存在できず、説明のあるエンドポイントが存在しないこともありえない。公開かどうかは `cond` の節のそばのコメントではなく宣言であり、だからこそテストがそれを検査できる。

## 生成され、ゲートされる

`telemachus-docs describe` は、ツールレジストリ、プラグインローダ、ワークフロー仕様、権限カタログ、ルート表を評価して一つの JSON モデルにする。`render` が `docs/reference/` を書き、`check` が再生成して一バイトでも違えば失敗する。出力はコミットされるので、ツールの引数を変えるプルリクエストは、同じ差分の中にドキュメントの変更を示す。すべての説明はカタログの中の `doc.*` メッセージでもあり、他のすべてと同じマネージャで翻訳される。

    racket cli/telemachus-docs.rkt render      # docs/reference/ を再生成する
    racket cli/telemachus-docs.rkt check       # CI のゲート
    racket cli/telemachus-docs.rkt render --locale ja

したがってエンドポイントを追加するのは、表に一つのエントリ、対応表に一つのハンドラ、一度の render、一度のコミットである。render を忘れれば CI が落ち、どちらかの半分を忘れれば起動が拒否される。
