# このプロジェクトはどう試験するのか


- **ユニットスイート**（`test/*-tests.rkt`）は、新しいデータベースに対して `domain/` を直接動かす。両方の方言で走る。パイプライン全体も、テストのプロセスの中で待ち行列を汲み出すことで、本物のスケジューラを通して走る。

- **スモークスクリプト**（`test/server-smoke.sh` とその仲間）は本物のサーバを起動し、`curl` で HTTP 越しに検査する。*モデルだけでなくエンドポイントを試験すること*。翻訳マネージャで実際に噛みついたバグは HTTP の層に住んでいた。問い合わせの絞り込みが文字列をシンボルの鍵と比べ、静かに既定値へ落ちていたのである。

- **端から端までのゲート**（`test/e2e/validate.sh`）はヘッドレスのブラウザでコンソールを操り、捕まえられなかったページのエラーと 5xx のいずれでも失敗し、台本を与えた模擬モデルに対してドキュメントパイプライン全体を走らせる。これが配備のゲートである。スクリーンショットの巡回は何も検査しないので、壊れたページでも写真に撮る。

- **モックはサーバである。** `test/mock-llm.rkt` は決定的な OpenAI 互換のモデルで、エージェントループのためのツール呼び出しモードと、パイプラインのためのチャットモードを持つ。

- 何かを完了と呼ぶ前に **PostgreSQL で確かめる**。すべてが `DATABASE_URL` を尊重する。

- **CI のゲート**は、ユニット、スモーク、マルチテナンシー、本物の `aws` クライアントに対する S3 エンドポイント、翻訳のゲート（英語は必須、他のロケールは助言）、ドキュメントの差分ゲート、端から端までのゲート、そして導線のブラウザテストである。

**飛ばせるスイートは隠せるスイートである。** S3 のスモークは `aws` の CLI が無いとき綺麗に終了する — だから資格情報の秘密鍵が保存時に暗号化されたとき、署名付きリクエストごとにそれを復号する経路は一度も動かされなかった。どの開発機にも、どの CI の実行環境にも、そのクライアントが無かったからである。いまクライアントは開発シェルに入っており、CI でも導入される。そしてスイートは秘密を封じた状態で走る。それが本物の配備が走る姿である。同じスイートは Nix のシェルの外で走ったことがなかったので、自分のコレクション経路を設定する必要に出会ったこともなかった。CI での最初の実行はライブラリを読み込めず、「サーバが立ち上がらなかった」と報告した。

**ブラウザにしか見えないものがある。** コンソールのインラインハンドラを変換したとき、ちょうど一つがテンプレートリテラルではなく引用符の文字列の中に残った。だからそれは文字どおりのテキストとして描かれ、導線の送信ボタンは何もしなかった。静的検査はすべて通った。ブラウザのテストがボタンを押し、時間切れになった。静的検査が*可能な*ところでは、後から書くこと。あの変換が依存する二つの不変条件は、いまコンソールをファイルとして読むユニットテストに固定されている。

テストが教えてくれた習慣をいくつか。同じ秒に作られた二つの行に「新しい順」を決して検査しないこと。背景のサーバは PID で殺し、パターンで殺さないこと（`pkill -f` は自分自身のコマンド行にも合致する）。ドキュメントを作るテストは、ブロブのルートを一時ディレクトリへ向けなければ、チェックアウトの中へ書き込んでしまう。
