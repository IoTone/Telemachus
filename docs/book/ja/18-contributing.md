# 貢献する


- 始める前に `CLAUDE.md` を読むこと。そして時間を費やして学んだことがあれば、そこへ書き足すこと。それがこのプロジェクトの記憶である。

- SQL は方言に依存させず、スイートを両方の方言で走らせること。

- モデルに面するすべての機能は検証し、拒否する。すべての AI 呼び出しは計量される。すべてのリソースは `can?` を通して検査される。

- 静かに劣化するのではなく、声を上げて拒否すること。読めない返答、未知のテーマのトークン、復号できない秘密、モデルが守らなかったスキーマ — これらはすべて自分の名を告げるエラーであり、空文字列でも、落とされたフィールドでも、静かな既定値でもない。このプロジェクトが追いかけることになったバグのほとんどは、何かが礼儀正しく失敗していたものだった。

- ルート、ツール、ワークフロー、権限を足せば、生成されるリファレンスが変わる。同じ変更の中で再生成してコミットすること。

- 利用者に見える新しい文字列は、三つのうち正しい住所へ置き、それから抽出器を通す。ゲートが必須とするのは英語である。他のロケールは網羅率である。

- 方針の分岐があるものは、まず設計すること。`docs/design/` の下に短い文書を置き、データの形、どのバックエンドでも実装できる契約、そして確認すべき決定を書く。決定ログは `docs/design/decisions.md` である。

- コミットメッセージは、何をどう検証したのかを言う。スライスが完了するのは、ユニットスイート、スモーク、ゲート、そして `nix build` が、両方のデータベースで一致したときである。
