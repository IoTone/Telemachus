# Localization


## Three homes

Server refusals live in `surface/messages.rkt`; the console’s chrome in `static/ui-strings.json`; the generated documentation’s prose in `docs/reference/strings.json`. All three are *surfaces* for one extractor, which folds them into `locales/en.json`, the base catalog. Translations live beside it, each string pinned to the hash of the English it was made against: editing the English makes the translation stale automatically, in every language, with nothing rewriting a status. The funnel’s operator-authored copy is the exception — an overlay on the experience document, not a catalog — because it is content, not code.

Resolution is the request’s locale header, then the instance default. An unknown locale falls back to the instance default, not to English; a Japanese-default instance is possible.

## The Localization Manager

The flagship: the platform building a real tool out of its own primitives. Catalogs on disk stay the shipping artifact; two tables are the workflow around them. *Missing* and *stale* are derived, never stored. A translator cannot approve their own string. AI drafting is a queue of scheduler jobs, twenty strings each, quota-metered — and a bulk draft stops when the team is over budget, which looks like a hang and is the platform working. A draft that loses, invents or mangles a placeholder is refused; the check counts braces, because the formatter is lenient by design and accepts exactly the drafts that need refusing. Dutch and Latin American Spanish were produced with this tool, every string reviewed, and pass the tool’s own gate.

## Whose clock it is

A locale decides which words somebody reads; a timezone decides which hour they read
on. They arrived separately and the second is the smaller subsystem with the sharper
traps.

**It is an IANA name, never a stored offset.** An offset is wrong half the year in
most of the world, and a schedule asks about the *future*, where only the rule can
answer. The name is validated against the database on disk, like the list of
available locales, so an unknown one is refused rather than quietly substituted:
somebody given UTC for a typo finds out from a report that arrives at the wrong hour.

**The layers do not tighten, and that is the opposite of the session policy
deliberately.** A person’s choice wins over their company’s, which wins over the
instance’s, which falls back to UTC — where a session timeout has the instance own
the floor and a company only able to shorten it. A timeout governs what is
*permitted*; a timezone governs how a number is *rendered*, and nobody is protected
by being forced into the wrong clock. The report names the layer that answered.

**The zone database is built slim, and the footer is the normal path.** A zone’s
transition table stops where its rule became regular — one European zone’s last entry
is in the 1990s — and everything after it is a compact rule string in the file’s
footer. A reader that walked only the table would answer today’s question with a rule
from thirty years ago, and a scheduler only ever asks about the future. The sign in
that rule string is also inverted from the one everybody expects, which is a
sixteen-hour error that still looks like a plausible time of day.

**Converting a local time to an instant answers three things, not one**: it worked, no
such instant exists, or two do. Twice a year an hour is skipped and an hour repeats,
so “07:00 local” is not always one moment, and the caller decides what to do about it
— a schedule passes the skipped morning over and records why, because firing at some
other time is a schedule that silently moved and inventing the instant is a lie. The
implementation needs two probes either side of the day, because the offset depends on
the instant while the instant is what is being solved for; a single round-trip check
cannot see the repeated hour at all, and reported the second 01:30 as fine.

Stored timestamps stay UTC, all of them — the same line the funnel’s translation
overlay draws between presentation and data. And the container has no system zone
database, so the path to one is declared in the build closure: without that, every
zone resolves to UTC on every real install while working perfectly in a checkout.
