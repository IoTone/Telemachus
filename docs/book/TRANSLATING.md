# Translating the developer e-book

The book is **one Markdown file per chapter**. There is no LaTeX to edit: the
preamble, the chapter sketches, the table of contents and the title page are all
assembled by `build.sh` from `chapters.json` and `template/book.latex`. A
translator works only in `<lang>/*.md`.

```
docs/book/
  chapters.json        the chapter ORDER, each chapter's sketch and its flags
  en/*.md              the English source, one file per chapter
  en/book.yaml         title, subtitle, author, date for the English edition
  ja/*.md              the Japanese edition — translate these
  ja/book.yaml         the same metadata in Japanese, plus the CJK fonts
  template/book.latex  the LaTeX preamble (nobody needs to touch this)
  art/                 the chapter sketches, generated by art/vignettes.py
```

## The workflow

1. Copy an English chapter across and translate the prose:
   `cp en/04-authz.md ja/04-authz.md`
2. Build the edition. Missing chapters are **omitted and listed**, so a partial
   translation always produces a readable book:
   ```sh
   nix develop          # from the repo root
   bash docs/book/build.sh ja
   ```
3. When a chapter has been checked against the current English, stamp it:
   ```sh
   bash docs/book/build.sh ja --record
   ```
4. Commit `ja/*.md` together with the built `telemachus-for-developers.ja.pdf`
   and `.ja.html`, exactly as the English edition is committed beside its source.

## The rules the build enforces

**A chapter begins with one `# Title` line.** Translate the title. It becomes the
chapter heading in both editions; the heading's anchor is taken from
`chapters.json`, not from the title, so translating it cannot break a link or
lose the chapter's sketch.

**A code span must be ASCII.** Text inside backticks names a file, a function, an
environment variable or a command — `domain/authz/authz.rkt`,
`TELEMACHUS_MODEL_URL`, `raco test` — so it is never translated, and a full-width
character or a typographic quote inside one is always a mistake. A Japanese input
method produces them easily. The build **refuses** and names the file, the span
and the character:

```
ja/04-authz.md: code span `'unsafe-inline'` contains U+2019
refusing to build: a code span must be ASCII (1 offender(s))
```

**Scripts that belong in no edition are reported.** Cyrillic, Hangul, Arabic,
Hebrew, Thai and Devanagari characters in the prose produce a warning. This is
not hypothetical: the project's machine-assisted Japanese catalog came back with
French, Spanish and Chinese fragments, and the first sample chapter written here
shipped a Russian word in the middle of a Japanese sentence.

**A stale translation is reported by name.** Each translated chapter carries the
sha1 of the English chapter it was made against, on its first line:

```markdown
<!-- source-sha1: 4f47c9729709289ad945741f7a003bb11363248d -->
# はじめに
```

Editing the English marks the translation stale with nothing rewriting a status —
the same rule `locales/ja.json` and `docs/screenshots/captions.ja.json` live by.
Leave that line alone; `--record` writes it.

## Terms

The book and the product must use the same word for the same thing. These come
from the console's own Japanese catalog (`refimpl/racketmaximus/locales/ja.json`),
which is the authority — if one of them looks wrong, fix it there and the book
follows.

| English | Japanese | catalog key |
|---|---|---|
| Documents | ドキュメント | `ui.documents` |
| Repository | ドキュメント保管庫 | `ui.repository` |
| Notes | ノート | `ui.notes` |
| Workflows | ワークフロー | `ui.workflows` |
| Jobs | ジョブ | `ui.jobs` |
| Automations | 自動化 | `ui.automations` |
| Knowledge | 知識 | `ui.knowledge` |
| Localize | 翻訳管理 | `ui.localize` |
| Usage | 使用状況 | `ui.usage` |
| Admin | 管理 | `ui.admin` |
| Audit log | 監査ログ | `ui.audit` |
| Branding | ブランディング | `ui.branding` |

Names that stay in English: **Telemachus**, **Racket**, **Nix**, **PostgreSQL**,
**SQLite**, **S3**, **SigV4**, HTTP verbs, and every identifier in a code span.

Register: system messages use です／ます. The console's Spanish catalog was
normalized to *usted* for the same reason — a tool talking to a stranger.

## Adding a language

1. `mkdir docs/book/<lang>` and write `<lang>/book.yaml`. Copy `ja/book.yaml` and
   translate the fields. A CJK language needs the two font lines it carries;
   those fonts are in the Nix devShell.
2. Translate chapters into `<lang>/`.
3. `bash docs/book/build.sh <lang>`.

Nothing else changes: `chapters.json`, the template and the art are shared by
every edition.

## Adding or changing a chapter (for maintainers)

See the book section of `CLAUDE.md`. In short: write `en/NN-stem.md`, add a row to
`chapters.json` and a scene to `art/vignettes.py`, then
`python3 art/vignettes.py && node art/render.mjs && bash build.sh`. Every
translated copy of a changed chapter goes stale and says so on the next build.
